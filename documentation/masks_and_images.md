# Masks and Images Reference

This file documents every mask/image type produced or consumed by the pipeline and where it is stored.
Update this when any new mask or image artifact is added.

## Source Images

- Donor (original)
  - Path: `assets/original/donor_image/<product>.tif`
  - Source product image.
- Donor (processed)
  - Path: `assets/processed/donor_image/<product>.png`
  - 4k-resized donor used for all processing.
- Color reference (original)
  - Path: `assets/original/color_reference/*.tif`
- Color reference (processed)
  - Path: `assets/processed/color_reference/*.png`
- Piping reference (original)
  - Path: `assets/original/piping_ref_images/*.png`
- Piping reference (processed)
  - Path: `assets/processed/piping_ref_images/*.png`

## Output Images

- Final composite result
  - Path: `output/<product>/<short>_<PID>_<model>_F..._R<idx>.png`
  - Final image saved after post-processing/composite.
- Raw model output (when post-processing disabled)
  - Path: `output/<product>/<short>_<PID>_<model>_F..._R<idx>.png`
  - Saved if `--no-post` or `--bare` is used.

## Recent Artifact Buckets

All run artifacts are stored under:
`output/<product>/recent/`

- `submitted/edit/`
  - `edit_donor_*.png`: donor image sent to edit API.
  - `edit_mask_*.png`: edit mask sent to edit API (padded to model input size).
- `submitted/mask/`
  - Donor or mask inputs sent to mask APIs (model, segmentation).
- `returned/mask/`
  - Mask outputs from APIs or generated post masks.
- `returned/result/`
  - Raw model outputs returned by the edit API.
- `returned/post/`
  - Post-processed outputs and diagnostic overlays.

## Mask Types

### 1) Manual/Static mask (user-provided)
- Purpose: A fixed mask used when no mask generation is requested.
- Expected: White = editable/visible; Black = immutable.
- Path (default): `assets/masks/<product>.png`
- How it is used:
  - Loaded by `find_mask_for_product(...)` when `--no-model-mask-pass` and no other generator is active.
  - Sent to edit API and used for post composite.

### 2) Model cushion mask (model mask pass)
- What it is: A binary mask generated by the Gemini/Vertex model from a MID prompt (currently tuned to cushion coverage).
- Prompt file: `prompts/mask_pass/mask_prompt_MID-<PID>_cushion.md` (fallback: `mask_prompt_MID-<PID>.md`, then MID-3).
- Generation:
  - API: `generate_piping_mask(...)`
  - Thresholded to binary and clipped to donor alpha.
- Saved files:
  - `output/<product>/masks/<short>_<PID>_mask.png`
  - `output/<product>/recent/returned/mask/model_cushion_mask_*.png`
  - Edit mask sent to API: `output/<product>/recent/submitted/edit/edit_mask_*.png`
- Usage:
  - Used for post composite (what part of the raw model output becomes visible on the donor).
  - Also used as the edit mask unless an alternate edit mask is explicitly chosen.

### 3) Donor piping mask (pre-edit, always-on)
- What it is: A binary mask of the existing piping detected on the donor image before any edits. This is always generated.
- Prompt file: `prompts/mask_pass/mask_prompt_MID-<PID>_donor_piping.md`.
- Saved files:
  - `output/<product>/masks/<short>_PID-<PID>_donor_piping_mask.png`
  - `output/<product>/recent/returned/mask/donor_piping_mask_*.png`
  - Submitted donor (mask input): `output/<product>/recent/submitted/mask/donor_piping_donor_*.png`
- Usage:
  - Diagnostic/QA and alignment checks.
  - Not used for edit or composite (model cushion mask is used instead).

### 4) Segmentation mask (Gemini segmentation)
- What it is: A mask parsed from a segmentation response.
- Prompt file: `prompts/mask_pass/mask_prompt_MID-<PID>_seg.md`.
- Saved files:
  - `output/<product>/recent/returned/mask/segmentation_mask_*.png`
  - `output/<product>/recent/returned/mask/segmentation_response_*.json`
  - `output/<product>/masks/<short>_<PID>_mask.png`
- Usage:
  - Used for edit mask and post composite.

### 5) Post-mask pass (mask from output) — disabled
- What it is: A mask generated from the *edited output* using a piping-mask prompt.
- Status: Disabled. We do not generate or use this mask for compositing.
- Notes: The donor piping mask is the only composite mask.

### 6) Calibration overlays
- What they are: Donor with mask painted red for visual vetting.
- The overlay always reflects whichever mask was most recently generated or selected.
- Saved files:
  - `output/<product>/recent/returned/post/cal_mask_*.png`
- Usage:
  - Visual QA only (not used in generation).

## Notes

- Post composite always applies donor alpha, so pixels outside the donor silhouette remain transparent.
- The edit mask sent to the model is padded to the model input size.
- SAM2, cushion-mask, and diff-mask features are disabled; the pipeline will fail if they are requested.
- If you change mask locations or add new mask types, update this file.
